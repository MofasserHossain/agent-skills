---
name: intake
description: "Turn meeting notes, documents, messages or existing tickets into a source-linked work brief."
---

Read the supplied material and accessible referenced sources. Record which sources were read and which remain unavailable. Connected read tools may supply context; pasted source text is sufficient when no integration exists.

Extract the problem, intended outcome, explicit requirements, suggestions, decisions and constraints. Keep assumptions visible. Surface contradictions rather than selecting an interpretation silently. Identify separate work items when the input combines unrelated requests.

Check relevant project behavior and previous decisions before asking the user. Do not ask them to repeat facts already available.

Use [brief template](../../templates/brief.md) as a starting shape, omitting empty sections. The result names material questions and recommends a route. A sufficiently clear small task can proceed directly; a new brief is unnecessary when the existing ticket already supplies the same contract.

External ticket updates, messages and publication require task authorization. Preserving a source URL does not authorize writing to it.
