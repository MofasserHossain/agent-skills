# UI design record

Use only sections that help this work. The parent spec/task owns requirements, acceptance criteria and task status.

## Audience, task and outcome
Actual users, context/platform, existing constraints and what success looks like.

## Baseline and questions
Observed problem versus hypothesis; existing screens/components and evidence pointers.

## Research findings
Question -> source/date -> finding -> relevance/limitations -> decision implication.

## Flow and relevant states
Entry -> action -> feedback/recovery -> exit. Include a diagram or state table when useful.

## Interface and data boundaries
Existing components/tokens, supplied data/API contract, mock data and unresolved assumptions.

## Options and selected direction
Only material alternatives; chosen behavior/appearance, rationale and review evidence. Link prototypes/screenshots and their revisions.

## Handoff and checks
Links to the authoritative spec/task requirements; relevant runtime/accessibility/layout checks, remaining evidence gaps and human decisions.
