name: handoff
description: "Prepare a portable continuation record when work moves to another session, agent, workspace or person."
---

## Establish the current state

Read the authoritative work record, applicable instructions and latest evidence. Identify the target project/workspace, current revision and actual working-tree changes. Distinguish verified results from agent claims, planned actions and unperformed checks. An earlier conversation summary cannot override newer code or task evidence.

## Write the continuation

Use the [handoff shape](templates/handoff.md), omitting sections that add nothing. State the objective, settled decisions with reasons, unfinished acceptance criteria, blockers and the next concrete action. Point to canonical specs/tasks and useful evidence instead of copying whole documents or transcripts. Paths must be resolvable in the receiving environment; explain a required transfer rather than assuming a host path is mounted there.

Account for uncommitted/untracked work, local-only branches, required fixtures and active processes that affect resumption. Name what must be preserved, without embedding secrets or dumping the environment. Preserve existing task identities and status ownership; writing a handoff does not change acceptance or authorize publication.

## Check that work can resume

Walk the receiving agent's first action through the record: can it locate the source, identify the revision/remaining edits, load the relevant rules and know what is still undecided? Report missing access or artifacts explicitly. The handoff is ready when continuation does not depend on proprietary session memory or a guessed human answer. Creating the record does not itself launch another agent, copy credentials or send messages.
